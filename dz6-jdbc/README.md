# ДЗ 6. Работа с базой данных через JDBC (Spring Boot + JdbcTemplate)

Студент: Волынкина Ксения, BHEMBD-25.

Стек: Java 17, Spring Boot 3.2.4, Spring JDBC (`JdbcTemplate`, `NamedParameterJdbcTemplate`),
H2 (по умолчанию) / PostgreSQL 16 (профиль `postgres`), Gradle 8.7 (wrapper в репозитории).

## Запуск

```bash
./gradlew clean build                          # сборка + 9 интеграционных тестов (на H2)
java -jar build/libs/hello-spring-jdbc-0.0.1-SNAPSHOT.jar          # H2 в памяти
```

С внешней PostgreSQL:

```bash
docker compose up -d                           # postgres:16, БД/пользователь/пароль = messages
java -jar build/libs/hello-spring-jdbc-0.0.1-SNAPSHOT.jar --spring.profiles.active=postgres
# параметры подключения переопределяются переменными DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD
```

## API (context-path `/api`)

| Метод | URL | Что делает |
|---|---|---|
| GET | `/api/messages?page=0&size=30` | страница сообщений, новые сверху |
| GET | `/api/messages?author=Имя&page=0&size=30` | сообщения автора |
| GET | `/api/messages/{id}` | одно сообщение, `404` если нет |
| POST | `/api/messages` | `{"content": "...", "author": "..."}` → `201` |
| POST | `/api/messages/batch` | массив сообщений → `201`, вставка одним JDBC batch |
| DELETE | `/api/messages/{id}` | `204`, `404` если нет |
| GET | `/api/users` | список пользователей |
| POST | `/api/users` | `{"name": "..."}` → `201`, `400` если имя занято |
| GET | `/api/users/{id}` | пользователь, `404` если нет |
| GET | `/api/users/{id}/messages?page=0&size=30` | сообщения пользователя |

Ответ страницы: `{"content": [...], "page": 0, "size": 30, "totalElements": 47, "totalPages": 2}`.

## Что сделано по самостоятельной части

1. **Миграция на внешнюю БД** — драйвер PostgreSQL в `build.gradle`, профиль
   `application-postgres.properties`, `docker-compose.yml`. `schema.sql` написан на общем для
   H2 и PostgreSQL синтаксисе (`GENERATED BY DEFAULT AS IDENTITY`), поэтому один файл схемы
   работает в обоих режимах.
2. **Обработка ошибок** — `NotFoundException` → `404`, ошибки валидации и некорректные
   `page/size` → `400`, нарушение ограничений БД → `409`. Ответы в формате RFC 7807
   (`ProblemDetail`) через `@RestControllerAdvice`.
3. **Пагинация** — `page`/`size` (`size` от 1 до 100) вместо жёсткого лимита 30;
   `LIMIT ? OFFSET ?` + отдельный `COUNT(*)` для `totalElements`. Сортировка
   `created_at DESC, id DESC`: у сообщений одного батча время создания совпадает, `id` даёт стабильный порядок.
4. **Батч-операции** — `POST /messages/batch` (до 1000 штук): одна транзакция,
   `NamedParameterJdbcTemplate.batchUpdate` с `KeyHolder`, возвращаются созданные сообщения с id.
5. **Пользователи** — таблица `users` (уникальное `name`), `messages.user_id` — внешний ключ
   на `users(id)`. При создании сообщения автор находится по имени или создаётся.
   Поиск по автору — `?author=` и `/users/{id}/messages` (JOIN, индекс по `user_id`).

Стартовые данные загружаются в `ApplicationRunner` (`SampleDataLoader`), а не в конструкторе
сервиса: к этому моменту схема уже гарантированно создана.

виртуализация и Docker не запускается. Тесты и ручная проверка выполнены на H2.
